# OpenCode Configuration

User-level behavioral rules only — discovery and usage docs live in opencode's picker, skill `description`s, and CLI `--help`.

## Delegation

Opencode's default is direct handling — invert it for context-heavy work: subagent first, skill when you lack the knowledge, direct only for trivial or explicitly requested work. **Skill = knowledge you lack; subagent = context you want to protect.**

**Skill-not-subagent exceptions:** API/spec authoring (`openapi.*`/`swagger.yaml`, or FastAPI/NestJS/tsoa/zod-to-openapi/springdoc/drf generator code) → `api-design-skill` + its §Authoring Quality Gate at write time. Images/screenshots → always `image-analyzer-subagent` — keeps visual payloads out of primary context.

## opencode-init (per-project subset)

On "install agents in this repo"-style requests: recommend presets; preview with `--describe <agent>` / `--expand <preset>`; install with `--project . --preset X --yes` (`--prune` switches). Warn: opencode unions global + project config — a subset is only isolated on a clean slate (no global deploy); otherwise additive (CLI warns).

## MCP Routing

- **Atlassian:** disabled globally; project opts in via its own `opencode.json` with a FULL entry — v2 replaces `mcp.servers.<name>` atomically, so a bare `{"disabled":false}` stub (or a V1 `{"enabled":true}` stub) is inert: `{"mcp":{"servers":{"atlassian":{"type":"local","command":["npx","-y","mcp-remote","https://mcp.atlassian.com/v1/mcp"],"disabled":false}}}}` (project wins; `opencode-repo-setup-skill`). Without it, never call `atlassian_*` — use CLI/REST fallbacks.
- **Web:** `zai-web-search` for discovery when the URL/source is unknown (returns cited results); built-in `webfetch` when you already have the URL; `zai-web-reader` only on webfetch failure (>5MB, timeout, encoding).
- **Local files:** built-in `Read`/`glob`/`grep`; MCP resource tools are for MCP-server resources only; never configure a `filesystem` MCP server.
- **Office docs → Markdown:** 4-tier routing in repo-root `AGENTS.md` (markitdown → docling → image-analyzer → pdf-specialist).
- **CodeGraph/LSP:** per-project — `opencode-repo-setup-skill` enables them and appends the rule blocks to the project's `AGENTS.md`. Never call `read_mcp_resource`/`list_mcp_resources` regardless — runtime-denied; tool-list presence is an upstream bug.

Prefer `rg` over `grep` (auto-fallback if absent).

## Branch Workflow Signal

On `NEEDS_GIT_BRANCH_SETUP: true` from a subagent (subagents only signal; the primary handles): load `git-branch-workflow-setup-skill` → §Detection Logic → prompt per §Question Tool Spec (§Non-Interactive Fallback skips in headless/CI) → on accept, delegate to `repo-ops-specialist-subagent` with the §Delegation Spec payload → if skipped, write `.opencode/branch-workflow-skipped`.

Subagents may spawn subagents (Task tool, gated by a `permissions` rule `action:"subagent"`); hub-and-spoke preferred.

## Verification Gates

LSP is ambient, CLI is the gate. Before declaring a non-trivial task done: lint + typecheck always; tests on logic/tested-path changes; build on deps/config/entry-point changes. Discover commands from `package.json`/`pyproject.toml`/`Makefile`/README; if unknown, ask once and record in the project's `AGENTS.md`. Fix failed gates; state pre-existing breakage explicitly.

## Human-Readable Replies

Every substantive reply — primary or subagent, all sessions — carries a plain-language essence a non-engineer can act on: for each finding/decision, one line stating what it affects (users, data, revenue, compliance, delivery dates) and why it matters, before the technical detail. Keep evidence precise (`file:line`, commands, diffs); humanize the prose around it — write like a person briefing a stakeholder, not a checklist. Apply `unslop-skill` patterns by default: no "delve", "tapestry", "not X but X", em-dash abuse, or similar AI-tell phrasing.

## Skill Allowlist

`{"permissions":[{"action":"skill","resource":"*","effect":"deny"},{"action":"skill","resource":"<skill>","effect":"allow"},…]}` (deny-all skill rule first, allows after — last matching rule wins) — denied skills cost zero primary context. New skills default hidden: for primary visibility allow in `opencode.json` + the `lean` array (`deploy/skill-profiles.json`); for subagent-only, allow in that agent's frontmatter. Never hand-edit deployed copies — re-run `setup.sh --skill-profile lean|full`.

## Commits

Conventional Commits `type(scope): description`; atomic (split migration/model/schema/logic/tests); body ≤72 chars (commitlint may override); never mix style-only with logic. Granularity: `git-semantic-commits-skill`.

## Memory Hygiene

Via `LEARNINGS/*.md` + the auto-inject manifest (the `memory` tool's plugin has no v2 release — pin removed; watch for a v2-compatible `opencode-superlocalmemory`); full procedure in `continuous-learning-skill`.
- **Recall:** `search` scope `project`, limit 5, before any review/plan/debug; if empty, proceed silently.
- **Capture:** ONE 2-line `add` per non-trivial fix/decision (`error-solution`/`architecture`/`learned-pattern`) — never routine commits, secrets, PII, or file contents.
- **LEARNINGS manifest** is auto-injected per session by the local plugin (ported to the v2 plugin API — active); `glob`+`read()` of `LEARNINGS/` remains the fallback.
- Scope: `project` = repo learnings; `user` = cross-project preferences.

## Secret Hygiene (advisory layer over vibeguard)

> **OpenCode v2 status:** vibeguard ships as a local v2 port (`plugins/vibeguard.ts`, engine from `opencode-vibeguard@0.1.0`) — masking is **active**. The `permissions` `read` deny rules remain the second layer. Rule 7 (fail-closed) still applies whenever masking is disabled or its config is missing.

Vibeguard masks `.env` secrets in provider-bound traffic and restores at tool-execution (hard control; the other is a `read` deny rule in the `permissions` array, primary only). These rules are advisory and defeatable:
1. Never echo `.env` values in reply text — `$VAR` names only; copy `__VG_…__` placeholders verbatim (broken ones fail to restore).
2. Subagents report key NAMES, not values — the placeholder→value map is per-sessionID.
3. Prefer `$VAR` env references in generated scripts/configs/commands.
4. Avoid unnecessary `.env` reads — not a substitute filter.
5. Never store secrets in `memory`, LEARNINGS, or commit messages.
6. Never `/share` a session that processed `.env` — plaintext export, no vibeguard hook.
7. Fail-closed: if vibeguard is no-op (missing/malformed/`enabled:false`), treat every `.env` value as exposed. Verify: `OPENCODE_VIBEGUARD_DEBUG=1 opencode` shows replace-counts > 0.
8. Project-root `vibeguard.config.json` **fully overrides** the global config (first wins, no merge — re-include regex patterns if you need both).

Details: `security-audit-skill`.
